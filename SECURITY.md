# Security reporting

Do not include credentials, private data, or exploit details in public issues. Use the repository's private vulnerability reporting channel if the host provides one. Otherwise ask a maintainer for a private contact route without disclosing sensitive details; no dedicated address is established in this bootstrap.

Include affected revision, reproduction steps, impact, and a suggested mitigation privately. There is no response-time guarantee or production service in Phase 0. Local development needs no secrets. Never commit `.env` files, private keys, or access tokens. Review dependency lock changes and update supported dependencies deliberately.
